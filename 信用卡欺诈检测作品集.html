OVERVIEW

项目概览

传统规则式反欺诈难以应对日益复杂的欺诈手段，机器学习为欺诈检测提供了新解法。

问题背景

信用卡欺诈每年给金融机构与消费者带来巨大经济损失。随着交易量增加，欺诈行为日益复杂多样，依赖规则与专家经验的方法难以招架。本项目运用数据挖掘与机器学习技术，构建分类模型预测交易是否欺诈，同时分析欺诈交易的特征模式与分布规律。

数据集

Kaggle 信用卡欺诈公开数据集（creditcard.csv）：

  • 特征V1~V28（PCA 处理后的数值特征）、Time、Amount
  • 标签Class：0 正常交易 / 1 欺诈交易
  • 规模284,807 笔交易，欺诈占比约 0.17%，极度类别不平衡

任务目标

  • 预测任务构建二分类模型，尽可能识别出所有欺诈交易（高召回率），同时避免过多正常交易被误判（可接受查准率）。
  • 描述任务通过 t-SNE 降维与聚类分析，揭示欺诈交易的特征模式、分布规律。
  • 评价指标核心：F1 分数、AUC-ROC；辅助：混淆矩阵、Precision-Recall 曲线。
INSIGHTS

数据洞察

围绕类别分布、金额、时间与特征变量开展探索性分析，为建模与特征工程提供依据。

阈值 0.6 时达到峰值 0.97525，此后略有回落

金额特征

  • 欺诈交易金额相比正常交易呈现"小而散"的特点。
  • 盗刷者为不引起卡主注意，更偏向小额消费。

时间特征

  • 每天 9:00–23:00 为信用卡消费高频时段。
  • Time 由秒转换为小时，便于周期特征建模。

特征筛选

  • V8、V13、V15、V20~V28 等 12 个变量无法很好区分类别，予以剔除。
  • V17、V16 等经随机森林重要性排序确认为关键特征。
METHOD

方法流程

完整实践数据挖掘全流程：预处理 → 类别平衡 → 特征工程 → 建模 → 评估调优。

五步流水线

Prediction + Description 双任务覆盖
STEP 01

数据预处理

Amount 缩放至 [0,1]，Time 由秒转小时；V1~V28 为 PCA 结果无需再处理。

STEP 02

类别平衡

应用 SMOTE 合成少数类过采样技术，使正负样本接近，缓解类别不平衡。

STEP 03

特征工程

随机森林 Gini/Permutation 重要性排序，剔除无效变量，降低维度与噪声。

STEP 04

模型构建

逻辑回归、随机森林多模型对比训练，抽取单棵树可视化验证学习结构。

STEP 05

评估调优

混淆矩阵 + ROC/AUC + PR 曲线全面评估，结合业务场景进行阈值调优。

过采样 SMOTE 合成少数类 特征选择 随机森林重要性排序 降维 t-SNE + 聚类分析 多模型 逻辑回归 · 随机森林
EVALUATION

模型评估

用混淆矩阵、ROC-AUC 与 Precision-Recall 曲线量化模型能力，并给出业务化的阈值选择策略。

混淆矩阵

预测欺诈预测正常
实际欺诈TP 真正例FN 假负例
实际正常FP 假正例TN 真负例
  • Accuracy / Precision / Recall / F1-Score 均由混淆矩阵导出。

ROC 与 AUC

  • AUC = ROC 曲线下面积，取值 [0,1]。
  • AUC=0.5 与随机猜测相当，AUC=1.0 完美分类，AUC>0.9 性能优秀。
  • 本项目各阈值下 AUC-PR 均高于 0.92，识别能力优秀。

PR 权衡

  • 召回率趋近 1.0 时精确率快速下降，体现"抓得越多、错得越多"的典型权衡。
  • 在高度不平衡数据中保持高召回率与较高精确率，表现难得。

高风险拦截优先阈值 0.1–0.3

大额、跨境交易等高风险场景，以高召回率确保欺诈被拦截，可牺牲部分用户体验。

综合性能最优阈值 0.6

AUC-PR 最高（0.97525），精确率与召回率平衡最好，适合大多数信用卡欺诈场景。

用户体验优先阈值 0.7–0.9

小额日常交易等低风险场景，减少对正常用户的干扰，接受一定程度的欺诈漏判。

SUMMARY

结论与收获

从问题定义到方案落地，完整走过数据挖掘全流程，并深入理解不平衡分类的评估与取舍。

关键收获

  • 数据预处理熟练应用 SMOTE 过采样技术处理类别不平衡问题。
  • 特征工程通过随机森林特征重要性识别出 V17、V16 等关键特征。
  • 模型构建实现逻辑回归、随机森林多模型对比与单树可视化。
  • 评估优化深入理解召回率/精确率的业务意义，掌握阈值调优方法。
  • 系统思维培养从问题定义到方案落地的完整思考与批判性思维。

不足与改进

  • 特征已 PCA 降维，缺乏原始交易的业务解释。
  • 缺少用户历史行为、商户信息等上下文数据。
  • 未考虑误报成本与人工复核流程等业务约束。
  • 未来可引入商户风险评分、地理位置等外部数据，尝试 CNN/RNN 等深度学习方法。
